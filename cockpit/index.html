# הקוקפיט: הפוסטים שלכם עולים לבד

הדביקו את כל הטקסט הזה ב-Claude Code (צריך מנוי Claude בתשלום, Pro ומעלה).
Claude יבנה איתכם מערכת שמפרסמת לאינסטגרם בשעה שקבעתם, דרך הממשק הרשמי של מטא, ושולחת לכם הודעה בטלגרם.
בשלב השני היא גם מתריעה כשפוסט ממריא, מזכירה כשעבר זמן מהפוסט האחרון, ואוספת נתונים.

מה צריך: חשבון Professional באינסטגרם (Business או Creator), וחשבונות חינמיים ב-Supabase, ב-Meta for Developers ובטלגרם.
כמה זמן: בערך 40 דקות. ברוב הזמן Claude עובד, ובכמה צעדים קצרים הוא יבקש מכם ללחוץ במסך של מטא.
כמה זה עולה: אפס דולר נוספים. הכל רץ על תוכניות חינמיות (לא כולל מנוי Claude).

---

You are setting up **cockpit**: a personal Instagram scheduler for one account. Finished posts go into a queue with one command, publish themselves at the scheduled time through Meta's official Instagram API, and report to the user on Telegram. It runs in the cloud on free tiers (Supabase + Telegram), so it works while the user's computer is off.

Speak to the user in Hebrew, in short plain sentences. Write all code, file names and commands in English.

## 0. Ground rules

- Build exactly the contract in sections 3 to 5. Command names, arguments, table and column names are fixed. Do not rename or "improve" them. Internal code structure is up to you.
- **Nothing is published to the user's Instagram without their explicit "yes" for that exact post.** This includes tests. Posts published through the API cannot be deleted through the API, so every test publish is a story (it disappears after 24 hours).
- **Secrets never pass through the chat.** Create `~/cockpit/.env` from a template, tell the user which line to fill, and let them paste the value into the file themselves. Never print a token, key or secret, not even partly. `.env` is in `.gitignore` and has mode 600.
- Never run `sudo`. If something needs an admin password, stop and give the user the exact one line to run themselves.
- One manual step at a time. Explain it in 2-3 short lines, wait for the user to say it is done, then verify it yourself before moving on (section 2 says how).
- Never declare the system ready before the acceptance test in section 7 passes in full. If a check fails, fix the cause and rerun the whole test. Show the real error, never claim success.
- Meta renames buttons often. If a screen does not match the words below, ask the user what they see and find the closest match. Never invent a step.

## 1. Preflight (check and report before anything else)

One short Hebrew list:
1. Node.js 20 or newer (`node --version`). Missing: point to https://nodejs.org and stop.
2. git (`git --version`).
3. The Supabase CLI runs with `npx supabase --version` (no global install).
4. Ask: is the Instagram account professional (Business or Creator)? If not: Instagram app, Settings, Account type and tools, Switch to professional account. It is free and reversible.

## 2. The user's manual steps (one at a time, in this order)

**A. Supabase (5 min).** Sign up at https://supabase.com, create a new project on the Free plan, choose the region closest to the user, save the database password in their password manager. Then the user runs `npx supabase login` in the terminal. You verify: `npx supabase projects list` shows the project. Save the project ref in `.env` as `SUPABASE_PROJECT_REF`. The user pastes the `service_role` key (Project Settings, API) into `.env` as `SUPABASE_SERVICE_ROLE_KEY`.

**B. Telegram bot (3 min).** In Telegram, open `@BotFather`, send `/newbot`, pick a name. The user pastes the token into `.env` as `TELEGRAM_BOT_TOKEN`, then sends any message to the new bot. You read the chat id from `https://api.telegram.org/bot<token>/getUpdates` (in code, never echo the token) and write `TELEGRAM_CHAT_ID`. You verify: send "הבוט מחובר" and ask the user if it arrived.

**C. Meta app (10-15 min).**
1. https://developers.facebook.com, My Apps, Create App. On "Add use cases" choose the Instagram one: **"Manage messaging & content on Instagram"** (in the docs it is called "Instagram API with Instagram Login"). Skip the business portfolio screen. The app stays in **Development mode**. For the user's own account this is enough, no App Review.
2. App roles, Roles, Add People, **Instagram Tester**, enter the account's username. Then in the Instagram app: Settings, Website permissions, Apps and websites, Tester invites, accept.
   - "Insufficient developer role" later always means this step is missing.
3. Instagram, API setup with Instagram business login, section "Generate access tokens": click **Generate token** next to the account and approve. A token from the dashboard is long-lived (60 days), so no login server is needed. The user pastes it into `.env` as `IG_ACCESS_TOKEN`.
4. You verify: `GET {IG_API}/me?fields=user_id,username` with the token returns the right username. Tell the user the username you see. Save `IG_USER_ID`.

## 3. Architecture (fixed)

```
~/cockpit/                 git repo: CLI, SQL migrations, edge functions, .env (ignored)
~/cockpit/bin/cockpit      the CLI (Node 20, no npm dependencies, built-in fetch)
~/cockpit/supabase/        migrations/ and functions/ for `npx supabase`
~/.claude/skills/cockpit/SKILL.md   the skill (section 6, verbatim)
```

Cloud (the user's Supabase project):
- Tables in section 3.2, RLS enabled on all of them with **no policies** (only the service role reads and writes).
- Storage: one public bucket `media`. Instagram fetches media from a public URL, so files must be there before publishing. Object names are random (uuid), so nobody can guess them.
- Edge functions (Deno, deployed with `--no-verify-jwt`, each refuses any request without the header `x-cron-secret` equal to the `CRON_SECRET` secret):
  - `publish-due`: every minute.
  - `refresh-token`: daily at 10:00 user time, refreshes when the token is older than 7 days, and on Sundays sends the heartbeat (3.5).
  - `remind`: daily at 09:00 user time (phase 2).
  - `metrics`: hourly (phase 2).
- Schedules: `pg_cron` + `pg_net` call the functions. `CRON_SECRET` is stored once in Supabase Vault (`vault.create_secret`) and read by the cron SQL at fire time, so it never lands in git. Same value set as a function secret with `npx supabase secrets set`.
- Telegram: one shared helper `sendTelegram(text)` in `functions/_shared/`.

### 3.1 Instagram publishing (fixed, these choices prevent known breakage)
- Host is `https://graph.instagram.com`, **not** graph.facebook.com. Keep the version in one constant, `IG_API = "https://graph.instagram.com/v27.0"` (the version in Meta's docs examples, Nov 2026). If a call fails with a version error, read the version in https://developers.facebook.com/docs/instagram-platform/content-publishing and update the constant; `v23.0` is known to work.
- Flow: create container(s) with `POST {IG_API}/{IG_USER_ID}/media`, wait until the container's `status_code` is `FINISHED`, then `POST {IG_API}/{IG_USER_ID}/media_publish` with `creation_id`. Then read `permalink` from the new media id. Use the account id, never `/me`, for these two calls.
- Types: one image = `image_url` (**JPEG only**, Meta supports no other image format), one video = `media_type=REELS` + `video_url`, story = `media_type=STORIES` with `image_url` or `video_url`, carousel = 2-20 children each created with `is_carousel_item=true`, then a parent with `media_type=CAROUSEL` and `children=<ids comma separated>`. A carousel counts as one post.
- Video processing can take minutes. **Never wait inside one function run.** Store the container id, set status `processing`, and check `status_code` once per minute on the following runs (Meta's recommendation). `ERROR` or `EXPIRED` means failed. A container expires after 24 hours.
- Publishing limit: Meta's own page says both 100 and 50 posts per 24 hours, so design for **50**. Before publishing, check `GET {IG_API}/{IG_USER_ID}/content_publishing_limit` and if the quota is used up, leave the post scheduled and tell the user once on Telegram.

### 3.2 Schema (one migration, `0001_cockpit.sql`)

```sql
create table posts (
  id            uuid primary key default gen_random_uuid(),
  short_id      text unique not null,            -- 6 chars, what the CLI shows
  kind          text not null check (kind in ('image','carousel','reel','story')),
  caption       text not null default '',
  media         jsonb not null,                  -- [{"path":"media/<uuid>.jpg","url":"https://...","type":"image"}]
  publish_at    timestamptz,                     -- null = draft
  status        text not null default 'scheduled'
                check (status in ('draft','scheduled','publishing','processing','published','failed','canceled')),
  container_id  text,
  ig_media_id   text,
  permalink     text,
  attempts      int not null default 0,
  last_error    text,
  claimed_at    timestamptz,
  published_at  timestamptz,
  created_at    timestamptz not null default now()
);
create index on posts (status, publish_at);

create table events (                             -- append only, the audit trail
  id bigint generated always as identity primary key,
  post_id uuid references posts(id),
  kind text not null,                             -- created|scheduled|claimed|processing|published|retry|failed|canceled|token_refreshed|alert_sent|reminded
  detail jsonb,
  at timestamptz not null default now()
);

create table tokens (
  id int primary key default 1 check (id = 1),    -- one account, one row
  access_token text not null,
  refreshed_at timestamptz not null default now(),
  expires_at timestamptz
);

create table metrics (                            -- phase 2
  post_id uuid references posts(id),
  ig_media_id text not null,
  taken_at timestamptz not null default now(),
  age_hours numeric not null,
  views int, reach int, likes int, comments int, saved int, shares int
);
create index on metrics (ig_media_id, taken_at);
```

`IG_ACCESS_TOKEN` from `.env` is copied into `tokens` once during setup. From then on `tokens` is the only source, and only the functions read it.

### 3.3 The publish engine (`publish-due`, every minute)
1. **Atomic claim.** An RPC `claim_due(p_limit int default 2)` flips due rows (`status='scheduled' and publish_at <= now()`) to `publishing` with `claimed_at = now()` and `attempts = attempts + 1`, using `for update skip locked`. Two overlapping runs can never claim the same post. This prevents double posting.
2. For each claimed post: create the container(s), save `container_id`, set `processing`.
3. Every run also checks all `processing` posts: `FINISHED` means publish now, save `ig_media_id`, `permalink`, `published_at`, status `published`, send Telegram `✅ פורסם` with the permalink. `ERROR`/`EXPIRED` means status `failed`.
4. Transient errors (network, 5xx, rate limit) put the post back to `scheduled` with `publish_at = now() + 2 minutes`, up to 3 attempts. After that: `failed` and Telegram `❌ לא פורסם` with the post's short id and the real error message from Instagram.
5. Reaper: a post in `publishing` or `processing` for more than 15 minutes goes back to `scheduled` (one retry) and is logged.
6. Every state change writes a row to `events`.

### 3.4 Token
Permissions: `instagram_business_basic` and `instagram_business_content_publish` (publishing), plus `instagram_business_manage_insights` (phase 2 numbers). `refresh-token` calls `GET https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=...` (the token must be at least 24 hours old and not expired; a token not refreshed for 60 days is dead for good), stores the new token and `expires_at`. If refresh fails, or the token expires in under 10 days: Telegram `🔑 החיבור לאינסטגרם עומד לפוג` with what to do (generate a new token as in step 2C.3, then `cockpit token`).

### 3.5 Keeping the free project awake
Supabase may pause a Free project after 7 days of low activity, and then everything stops silently. Its docs say real requests to the project count as activity, but they never say whether `pg_cron` does. So:
- The cron jobs call the functions through the project's public URL (`https://<ref>.supabase.co/functions/v1/...`), as real HTTP requests.
- `refresh-token` also sends a weekly heartbeat every Sunday at 10:00 user time: `💓 הקוקפיט ער. בתור: <n> פוסטים`. Tell the user: **if Sunday's heartbeat did not arrive, open the Supabase dashboard and click Restore project.** Opening the dashboard also counts as activity.
- `cockpit status` reports if the project is paused.

## 4. The CLI (`cockpit`)

Every command prints a short Hebrew result. `--json` prints JSON instead. **An unknown command or argument exits with code 2 and a clear message.** Times are the user's local time zone (read it from the system), stored as UTC.

| Command | Does |
|---|---|
| `cockpit add <file...> --at "YYYY-MM-DD HH:MM" [--caption "..." \| --caption-file f.txt] [--story] [--draft]` | Detects the kind: one `.jpg`/`.jpeg` = image, 2-20 images = carousel (in the given order), one `.mp4`/`.mov` = reel, `--story` = story. Converts nothing silently: a PNG is refused with a message on how to convert. Uploads to `media/<uuid>.<ext>`, inserts the post, prints its short id and the local publish time. `--draft` saves without a time. A time in the past is refused |
| `cockpit list` | Upcoming and recent posts: short id, kind, local time, status, first words of the caption |
| `cockpit show <id>` | One post with its events |
| `cockpit move <id> --at "..."` | New time for a scheduled or draft post |
| `cockpit cancel <id>` | Cancels a post that has not been published. A published post cannot be canceled (say so) |
| `cockpit status` | Token days left, last `publish-due` run (from `cron.job_run_details`), queue size, posts published this week, quota left |
| `cockpit token` | Copies a new `IG_ACCESS_TOKEN` from `.env` into `tokens` after the user replaced it |
| `cockpit stats` | Phase 2: the last 10 published posts with views, saves and shares, best first |
| `cockpit selftest` | Runs section 7, part 1 |

## 5. Phase 2: it tells you what to do (only after phase 1 passes, ask the user first)

- `metrics` (hourly): for every post published in the last 7 days, read its insights (`GET {IG_API}/<media id>/insights?metric=views,reach,likes,comments,saved,shares`; do not ask for `impressions`, Meta retired it for new media) and add a row to `metrics` with its age in hours.
- **Takeoff alert** (inside `metrics`): when a post between 1 and 6 hours old has views at least 2 times the median of the user's own previous 10 posts at the same age, and at least 100 views, send once ever per post: `🚀 הפוסט ממריא. זה הזמן להיכנס להגיב` with the permalink. Fewer than 5 previous posts: no alert yet (no baseline).
- **Reminder** (`remind`, daily 09:00): if no post was published in the last 4 days and nothing is scheduled for today, send once that day: `♟️ עבר זמן מהפוסט האחרון. יש משהו בתור?`.
- Log every alert in `events` (`alert_sent`, `reminded`), so nothing is sent twice.

## 7. Acceptance test (must pass before you say the system is ready)

**Part 1, `cockpit selftest` (nothing is published):** print each line as pass or fail.
- The token works: `/me` returns the expected username.
- All four tables exist, RLS is on, and an anon request to `posts` returns nothing.
- `cron.job` lists the jobs, and `cron.job_run_details` shows a successful `publish-due` run in the last 3 minutes.
- Each function returns 401 without `x-cron-secret` and 200 with it.
- `cockpit add` with a fake argument exits with code 2. A time in the past is refused. A PNG is refused.
- A draft added with `--draft` appears in `list` and is removed by `cancel`.
- `claim_due` run twice in parallel on one test row claims it exactly once (then the test row is deleted).
- Telegram: send `בדיקה: הקוקפיט מחובר` and ask the user to confirm they got it.

**Part 2, one real story (only with the user's explicit yes):** ask the user to pick any photo they are fine showing as a story for 24 hours, convert it to JPEG 1080x1920 if needed (ask before converting), and run `cockpit add <file> --story --at <now + 3 minutes>`. Watch `cockpit show` until `published`. If the story fails with an account-type error, stop and tell the user the real error. Never fall back to a feed post as a test (a feed post cannot be deleted through the API). Pass only when: status is `published`, `ig_media_id` and `permalink` are set, the user confirms the story is on their profile, and the Telegram `✅ פורסם` arrived.

Only when both parts pass: tell the user, in Hebrew, that the cockpit is ready, and that from now on they can say "תכניס את הפוסט הזה לתור למחר ב-20:00". Then offer phase 2.

## 8. Not in this version

No web dashboard, one Instagram account only, no comment or DM automation, no first comment, no collaborators, no music on reels (the API does not add music), no editing a caption after publishing, no deleting published posts (the API does not support it). If the user asks, say it is not in this version.
